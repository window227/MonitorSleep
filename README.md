# 显示器睡眠助手（MonitorSleep）

一个 Windows 11 托盘小工具：**按需关闭显示器省电**，并且**在该保持常亮的时候绝不关屏**。

---

## 这个程序解决什么问题

Windows 自带的「N 分钟后关闭显示」是个死板计时器：看视频、开会、跑全屏程序时照关不误。
于是大多数人干脆把它设成「从不」，结果显示器整天亮着，反而更费电。

本程序反过来做：

1. 把系统的「在此时间后关闭显示」改成**从不**（接管）；
2. 由自己判断**现在该不该关屏**——空闲足够久、且没有在看视频/开会/演示/跑全屏；
3. 退出或崩溃后，自动把系统设置**还回去**。

一句话：**该关的时候一定关，不该关的时候绝不关。**

## 快速开始

```
dist\Release\MonitorSleep.exe
```

双击即可，会出现在托盘（通知区域）。**不需要管理员权限**。

> 需要「.NET 8 桌面运行时」(Microsoft.WindowsDesktop.App 8.x)。
> 这台机器已经装好了（8.0.16）。别的机器如果没有，去微软官网装 ".NET Desktop Runtime 8"。

### 找不到托盘图标？

有**两种完全不同的原因**，程序会自己区分并弹框告诉你：

#### 原因一：Windows 11 把新图标折叠起来了（正常情况）

**Windows 11 默认会把新出现的托盘图标折叠进任务栏右下角的「^」溢出区**，所以第一次运行大概率"看不见"。
点一下那个 `^` 就能找到它；想让它常驻：右键任务栏 → 任务栏设置 → **其他系统托盘图标** → 把本程序打开。

图标长这样：**一块蓝色的实心显示器**（屏幕内部是深色，左上角有一小块浅蓝高光）；
屏幕关闭时它变成**灰色，并压上一道红色斜杠**。

托盘菜单里有「让图标常驻通知区域…」直达该设置页；
另外 **任何时候双击 `MonitorSleep.exe` 都会直接打开设置窗口**（单实例机制），图标被藏起来也不影响使用。

#### 原因二：程序跑在受限（低完整性）环境里 —— 系统直接拒绝

如果弹框说的是"**运行环境受限**"，那就不是折叠问题，而是 Windows 根本不允许：

```
系统拒绝注册托盘图标（错误码 5：拒绝访问）
当前进程的完整性级别：Low（低）  S-1-16-4096
```

低完整性级别（Low IL，`S-1-16-4096`）的进程会被 Windows 一律拒绝三件事：

| 被拒绝的能力 | 表现 |
|---|---|
| 注册托盘图标 | 托盘上什么都没有 |
| 写 `%APPDATA%\MonitorSleep` | 配置永远存不下来 |
| 改写系统电源方案 | 「接管系统关屏」静默失效 |

三个症状看起来毫不相干，**根因是同一个**。

> ⚠️ 最常见的触发方式：**从某些受限工具（沙箱、自动化环境）里直接拉起 exe**。
> 正确的启动方式是打开「文件资源管理器」，进入程序目录，**双击 `MonitorSleep.exe`**。

用 `--diagnose` 可以直接看到这三项的状态：

```
完整性级别    : Low（低）  S-1-16-4096
托盘图标能力  : 被系统拒绝（错误码 5：拒绝访问）
配置写入测试  : 成功
```

三项都正常时应该显示 `Medium（中）  S-1-16-8192` / `可注册`。

## 功能

### 已实现

| 类别 | 功能 |
|---|---|
| **关屏** | 立即关屏；5/15/30/45/60/90/120 分钟后定时关屏（可取消） |
| **电脑睡眠** | 手动让电脑进入睡眠（热键 / 按钮 / 托盘菜单），同样先走可取消的倒计时。**刻意不做空闲自动触发** —— 睡眠会暂停所有程序，误触代价比关屏大得多 |
| **定时睡眠** | 托盘菜单「定时睡眠」或「设置 → 基本 → 定时」：5/15/30/45/60/90/120 分钟后让电脑睡眠，可取消。到点走与手动触发相同的倒计时流程，与「定时关屏」对称 |
| **自动关屏** | 按空闲时长自动关屏（默认 10 分钟） |
| **接管系统关屏** | 可选，**默认关闭**，在「高级」页。把系统超时改为「从不」；开启时会检查"是否反而更费电"并当场提示；退出/崩溃自动还原 |
| **关屏但保持系统运行** | 可选：屏幕关闭期间阻止系统睡眠（下载、转码、远程连接用） |
| **智能避让** | 全屏程序 / 演示模式、摄像头或麦克风占用中、远程桌面会话、自定义进程黑名单、刚解锁的静默期、电源策略（仅电池 / 仅插电）。「播放音频时保持常亮」**默认关闭**（见下方说明） |
| **防误报** | `QUNS_BUSY` 在部分环境会误报，额外核对前台窗口是否真的占满整块屏幕 |
| **防护** | 关屏前倒计时（手动触发也生效，可取消）；关屏失败时全屏黑窗兜底；退出与崩溃都还原系统设置 |
| **防自唤醒** | 关屏前先等键鼠安静 450 毫秒 —— 否则"按下热键 → 关屏 → 松开按键"里的**松手动作本身就是一次输入**，显示器会立刻被唤醒 |
| **集成** | 托盘菜单、全局热键（可自定义）、开机自启、单实例（再次启动会弹出设置窗口）、深色/高 DPI、中文界面 |

### 为什么「接管系统关屏」默认关闭

因为它是个**失效危险**的设计。接管 = 把系统超时改成「从不」，于是：

| 情况 | 后果 |
|---|---|
| 程序被强杀 / 被删除 / 判断出错 | 屏幕再也不会自动关闭，**比原来的设置更费电** |

而且 **Windows 本身并不笨**：浏览器播视频、播放器、PowerPoint 放映都会主动调用
`SetThreadExecutionState(ES_DISPLAY_REQUIRED)` 告诉系统「现在别关屏」。
所以接管想解决的那个问题，在正常应用上基本不存在。

默认设计是**两层各自独立**：

```
本程序：在系统超时之前，按避让规则决定何时关屏   （提前关）
Windows：保留自己的超时，作为永远不会失效的兜底   （兜底关）
```

任何一层挂掉，另一层还在。只有「某个不主动抑制关屏的程序确实需要屏幕长亮」时，
才建议到「高级」页手动打开接管 —— 打开时程序会自动检查是否反而让屏幕亮得更久，并当场提示。

### 为什么「播放音频时保持常亮」默认关闭

这条规则靠音量峰值判断，**分不清视频和纯音乐**，于是听歌时也会一直不关屏。
而 Windows 分得清 —— 它只给视频发显示唤醒锁，听音乐时照样关屏。
开着这条规则反而比系统行为更费电，所以默认关闭。

### 尚未实现（后续阶段）

- **DDC/CI 逐屏硬件断电**：能按显示器精确断电、最省电，且键鼠唤不醒；
  代价是部分显示器/转接器不支持，且断电后可能收不到「开机」指令，需要看门狗兜底。
- **关屏后吞掉键鼠输入（防误唤醒）**：需要低级钩子，能否真正拦住硬件唤醒**必须实测**，
  且容易被反外挂/杀软误报；不想在没验证过的情况下塞给用户一个开关。
- 亮度调节与关屏前渐暗（笔记本走 WMI，外接屏走 DDC/CI）。
- 每日时间表式计划任务、`monitor-sleep://` 协议、局域网 HTTP 触发。
- OLED 防烧屏的像素位移。

## 默认热键

| 操作 | 默认 |
|---|---|
| 关屏 | `Ctrl + Alt + O` |
| 电脑睡眠 | `Ctrl + Alt + S` |

可在「设置 → 基本」里改：点进输入框直接按组合键，`Backspace` 清除。

> 只保留两个热键：关屏与电脑睡眠（O = Off，S = Sleep）。唤醒屏幕靠任意键鼠输入就行，"切换"也没有必要。
> 热键被别的程序占用时（错误码 1409），本程序**不会**因此启动失败：托盘照常工作，
> 只是那条热键失效，并会弹气泡告诉你。用 `--diagnose` 可以查它们是否可用。
> 默认值就是这么挑出来的——本机 `Ctrl + Alt + M` 已被其它程序占用，`O` 和 `S` 才空着。

## 重要说明

- **关屏 ≠ 锁屏。** 本程序只关显示器，系统和所有程序继续运行。
  是否需要锁屏由 Windows 的屏保/锁屏策略决定，与本程序无关。
- **退出时一定会还原系统关屏设置。** 如果你手动把 `电源选项 → 关闭显示器` 改回去，
  程序下次启动会重新接管；想彻底交还控制权，请在设置里取消勾选「接管系统关屏」。
- **崩溃也不怕。** 关屏设置一旦被改写，就会在 `settings.json` 里留下待还原标记；
  下次启动第一件事就是还原，然后弹气泡告诉你上次没正常退出。
- 只对本地控制台会话生效，不干扰远程桌面。

- **会改系统设置的选项放在最后的「高级」页**，不占显眼位置。

  短页面不会拖出一大片空白。

## 诊断模式

排查「为什么没关屏」时用这个（会打印避让判定的依据）：

```
MonitorSleep.exe --diagnose
MonitorSleep.exe --diagnose --test-sleep     # 额外实测关屏 2 秒后恢复
MonitorSleep.exe --diagnose --out 报告.txt
```

输出内容包括：远程会话、供电状态、shell 通知状态、前台窗口是否真的全屏、
系统空闲时长、音频/摄像头/麦克风占用、电源方案当前值与待还原值、
`INPUT` 结构布局校验、关屏热键能否注册、避让判定结论、当前配置摘要。

报告默认写到配置目录下的 `diagnose.txt`（UTF-8 带 BOM，记事本能正常打开）。

默认位置：`%APPDATA%\MonitorSleep\settings.json`

可用环境变量 `MONITORSLEEP_DATA_DIR` 改写（便于测试或做便携版）。

## 构建

```powershell
.\build.ps1                 # Release 编译
.\build.ps1 -Publish        # 发布到 dist\Release\
```

首次构建需要 .NET SDK（装在**工作区内**，不需要管理员权限）：

```powershell
.\.tools\dotnet-install.ps1 -Channel 8.0 -InstallDir .\.tools\dotnet -NoPath
```

`build.ps1` 会把 SDK、NuGet 缓存、临时目录全部限制在工作区的 `.tools` 下，
因此在受限（沙箱）环境里也能反复编译，不触碰工作区以外的路径。

本项目**刻意不引用任何 NuGet 包**（音频检测用原生 COM 互操作实现），
所以 `restore` 完全不需要联网。

### 已知的构建限制

- **单文件发布**需要一次带 `RuntimeIdentifier` 的 NuGet 还原，而还原会去写
  `%APPDATA%\Roaming\NuGet`。在受限沙箱里这个路径被拒绝，因此当前发布的是
  **多文件**形式（`MonitorSleep.exe` 148 KB + 3 个小文件，共约 216 KB）。
  在普通机器上直接跑下面这条即可得到单文件：
  ```powershell
  dotnet publish MonitorSleep\MonitorSleep.csproj -c Release -r win-x64 `
      --self-contained false -p:PublishSingleFile=true -o dist\Release
  ```
- **自包含发布**（`--self-contained true`，约 150 MB，目标机器无需装运行时）
  需要联网下载运行时包。

## 实测记录

在本机（Windows 11 25H2，build 26200.8655）上已验证：

- `SC_MONITORPOWER(2)` 关屏 → 显示器确实熄灭，2 秒后 `SC_MONITORPOWER(-1)` + 1 像素鼠标往返成功唤醒；
- 电源方案接管：交流 300 秒 / 直流 180 秒 → 改写为「从不」，原值记录在配置里；
- 崩溃自恢复：硬杀进程后系统仍是「从不」，重新启动后自动还原为 300 / 180，并清除待还原标记；
- 避让逻辑：`SHQueryUserNotificationState` 返回 `Busy` 但前台 Chrome 窗口并未占满屏幕，
  程序正确判定为「允许关屏」（未被误报挡住）；
- WASAPI 音频检测正常返回（未播放 → 否），摄像头/麦克风占用检测正常返回「否」；
- `INPUT` 结构布局为 40 字节，符合 x64 预期，合成输入可用。

## 伪唤醒抑制（兜底）

有些无线鼠标每隔几分钟切换一次节能模式，期间发出一条**零位移** HID 报告。
Windows 把它当成"用户回来了"，于是把刚关掉的屏幕又点亮 —— 屏幕就这样反复自己亮。

打开「设置 → 自动关屏 → 伪唤醒抑制」后，本程序会识别这种无效输入并把屏幕关回去。
只有真实的鼠标移动 / 按键 / 键盘操作才会打断它；连续抑制 8 次后自动放弃，不会和用户抢屏幕。

**默认关闭。** 启用前建议先跑一次自检，确认前提成立：

```powershell
MonitorSleep.exe --diagnose
```

自检会报告三项：

| 项目 | 含义 |
|---|---|
| **光标位移判据** | 兜底判据，判断鼠标是否真的动过 |
| **Raw Input 增强** | 收得到的话，键盘唤醒也能正确识别；收不到不影响兜底 |
| **显示状态通知** | 精确判据（系统通知）。实测某些环境下系统注册成功却一条都不发，收不到不影响使用 |
| **空闲推断退路** | 通知收不到时靠它：空闲时间超过系统关屏超时即认为屏幕已关。**这才是能不能用的真正依据** |

自检会把屏幕关掉约 2 秒再恢复，属正常现象。

> 这一项是**兜底**。根治办法是关掉鼠标自己的省电 / 休眠模式（厂商驱动里通常有），
> 以及设备管理器里各 USB 设备的「允许计算机关闭此设备以节约电源」。
### 睡眠侧

开关组里还有一项「**电脑被无效输入唤醒时，让它继续睡**」。
零位移报告不光会点亮屏幕，也会把电脑从睡眠里叫醒 —— 这一项让电脑继续睡。

恢复后有 6 秒反应时间，动一下鼠标就能取消；连续送回睡眠 3 次后自动放弃。

> ⚠️ 这一项比屏幕侧更强势（会真的让系统再次入睡），所以做成**独立开关**。
> 如果你有后台任务（下载、备份、Windows 更新）希望趁唤醒跑完，别开它。
